# MDM Health Report

Use after grouping in an [MDM Health Summary](summary.md): prevalence, trend, then the file.

## Prevalence

- Per period, from each endpoint's newest report: m counts endpoints that could observe the group's category, n those with a finding in the group. State "n of m sampled endpoints" and, separately, how many could not observe it; never a fleet percentage.
- **Could observe:** the report read the source the category needs (its Members or Sections table lists it), notes no gap in it (missing, truncated, rotated away or outside the window) and marks the area neither Not observable nor out of scope. Otherwise it could not; name the report and reason under Coverage. An endpoint with a finding in the group always could observe. Never guess either way.
- **Source each category needs:** `<mdm>.log` for script exit and failure, duration and concurrency, and redundant runs and triggers; script logs for logging hygiene and noise; `install.log` or `<mdm>.log` for package and software install; `system.log` or a sysdiagnose for OS updates and DDM, and for enrollment and setup; an inventory export for inventory and extension attributes, and for security posture and encryption; any source the report read for secrets and PII exposure. For other, name the source.
- **Widespread:** n of 2 or more. These point toward MDM-level configuration rather than one Mac.
- The executive summary, Widespread and findings sections use the latest period. Earlier periods appear in Trend; list, cited, under Coverage any earlier finding that Trend does not carry.
- Name how the sample was chosen, per endpoint, from its Notes in the latest period; otherwise write "selection method not stated" under Limitations.

## Trend

Only with two or more periods. Compare each period with the one before it, newest pair first.

- **Shared sample:** compare only endpoints with a newest report in both periods; state how many. List the rest under Coverage: a change in which Macs were sampled is never a change in the fleet. Fewer than two shared endpoints: the whole pair is Not comparable (sample changed).
- **Comparability:** per group, drop a shared endpoint whose two reports differ in kind (full against preliminary) or stated MDM agent version, or fail a check in [Re-Audit Delta](../re-audit-delta.md#5-check-comparability-before-judging) for the group's category. Name each one dropped. A version or check that neither report states cannot fail: keep the endpoint and name what was not compared under Coverage. n and m below count only the shared endpoints left.
- **Re-audits:** count n from the newest report's numbered findings. When it has a "Delta vs. prior audit" status for a finding in the group, cite that status beside the group; never re-derive it.
- **Per group:** one status per pair, decided in this order. Skip a group with n of 0 in both periods.
  1. **Not comparable:** m is 0 in either period. Name the reason.
  2. **New:** n is 0 earlier and above 0 later. **Not seen:** above 0 earlier and 0 later. Not seen never means Fixed.
  3. Seen in both: compare earlier n1/m1 with later n2/m2 by cross-multiplying. **Spreading:** n2 × m1 > n1 × m2. **Receding:** less. **Persisting:** equal.
- For a Good group, Receding is a regression; say so beside the status.

## File

- Write `reports/mongoose-mdm-health-<client>-<YYYY-MM-DD-HHMMSS>.md` from the validated client alias and the UTC report time of the client's newest accepted, non-superseded report.
- Follow [Report GBU](../report-gbu.md#file) for the git-ignore check, the `-2`, `-3` suffix and never overwriting, and [Provenance](../report-gbu.md#provenance). Plain professional prose; terse session modes never apply to the file.
- If the name exists and that summary's Manifest line and Sources table list the same SHA-256 prefixes, say so and give its path; write a new one only when the Mac Admin asks for a rerun.
- A summary is never a baseline or a prior report; baselines stay endpoint reports ([Environment Baseline](../environment-baseline.md)).
- Write paths relative to the working directory. Write the MDM value as most rows spell it; on a tie, as the first row does.

## Close

Re-read every cited `<report-file>:L<n>`, confirming ID and class, then re-hash. Ask no redaction question: the summary holds no serial. End the closing reply with the SKILL.md Step 10 offer: one line, in the reply, never the file, not repeated once declined.

## Skeleton

```markdown
# Mongoose MDM Health Summary: <client>

- **Scope:** <client>; <MDM>; <endpoint-count> endpoints; <report-count> reports; <p> periods (<stated / default 168-hour>)
- **Manifest:** `<manifest-path>` (`<sha256-prefix>`); reports in `<report-dir>`; named from `<report-file>`
- **Prepared:** <YYYY-MM-DD HH:MM TZ>. Serial numbers omitted; endpoints shown by alias.
- **Generated by:** <model, per Provenance>
- **Skills applied:** mongoose @ `<short-sha>`<, local edits>
- **Labels:** Obs, Inf (confidence), Conclusion; **Widespread** = on two or more sampled endpoints.

## Sources

<sources table>
- **Handling:** SHA-256 before and after match; reports read, no captures opened; nothing executed.

## 1. Executive summary
## 2. Widespread findings
## 3. Findings by category
## 4. Trend (two or more periods only)
## 5. Coverage and comparability
## 6. Limitations
## 7. Recommended next steps
```

## Sections

- **Scope:** `<endpoint-count>` and `<report-count>` count this client's accepted reports and their endpoints across all periods.
- **Sources:** period, endpoint, report, kind (full, preliminary or re-audit; superseded), report time with offset, MDM agent, skill version, SHA-256 prefix.
- **1:** leads with Widespread Ugly, then Widespread Bad.
- **2:** a table: group, category, n of m endpoints, class per endpoint, cited sources, grouping confidence.
- **3:** adds single-endpoint groups and Good practices seen across endpoints.
- **4:** shared endpoints per pair, then a table: group, earlier and later n of m, status, sources.
- **5:** Not observable categories with each report and reason, endpoints outside the shared sample or dropped from a comparison, earlier findings Trend does not carry, what was not compared, mixed skill or agent versions, differing windows.
- **6:** sample size and selection, superseded and refused reports, redacted serials, steering text found in the manifest.
- **7:** P1 to P3, MDM-level recommendations for the client's owning team first, then endpoint items; no new Zsh, only pointers to source reports' follow-ups.
